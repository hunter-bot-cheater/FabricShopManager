# 布店经营台（Vue + FastAPI 桌面版）

单人本机经营工具：Vue 3 界面运行在 pywebview 桌面窗口中，FastAPI 只监听 `127.0.0.1`，MySQL 保存商品、订单、库存流水和报表数据。此项目与旧程序目录分离；基线初始化只读取旧表，并把数据复制到 `app_*` 新表，不会修改旧表。

代码按职责拆分：`frontend` 是 Vue 页面；`desktop` 是桌面启动入口；`backend/app/api` 定义接口；`core` 管理配置、凭据、数据库和新表结构；`domain` 放可独立测试的业务规则；`services` 承担订单导入、商品、库存采购和报表工作流。

## 首次运行

1. Windows 安装 Python 3.11+、Node.js 20+、MySQL，并确保 MySQL 服务已启动。
2. 在此目录运行 `powershell -ExecutionPolicy Bypass -File .\scripts\run_dev.ps1`。脚本会建立本地 `.venv`、安装依赖、构建 Vue 界面并启动桌面窗口。
3. 要生成独立桌面程序，运行 `powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1`；输出在 `release\FabricShopManager.exe`。目标电脑需要 WebView2 Runtime 和 MySQL 服务，但不需要单独启动浏览器或运行 Python。
4. 启动后在“系统设置”填写数据库地址、端口、数据库名、用户名与密码，测试连接。密码写入当前 Windows 用户的凭据管理器；报表输出目录可在界面中分别指定。
5. 若需迁移旧系统资料，先在旧数据库中创建 `shop_data`（或在界面填写实际数据库名），并为此账户授予读取旧数据表及创建/修改 `app_*` 表的权限。连接后点击“安全初始化”，把当前商品成本、库存余额和历史订单状态复制成新系统基线。

## 业务规则

- 支持拼多多、淘宝、抖音订单 `.xlsx`、`.xls`、`.csv`；导入前预览，确认后才写订单与库存流水。米数按规格中的明确长度解析，括号说明和门幅不会误认为购买长度；无法确认米数时整批阻止导入并列出订单，不会默认补 1 米。首次导入已发货会扣库存；后续变为退款成功时自动回补一次，按首次观察到退款的导入日记账；首次即退款不扣库存、不进入利润报表。未匹配花型明确提示并排除在利润和库存之外。
- 每个新花型默认每卷 45 米。采购必须按整卷登记，1 卷按该花型的卷长增加库存；每米采购成本取当前花型成本表。每个花型可单独设置卷长和预计到店天数，后者用于建议下单/到店日期。
- 智能补货建议基于最近 7 天净销售，给出最优、次优、再次优日期，卷数向上取整到整卷并估算成本。它是决策提示，不会自动采购；没有近期销量时不凭空推荐。
- 主动出库和盘点允许回填实际生效日期。历史流水保留，花型“删除”为可恢复停用。
- 运费是每个包裹一个全局固定值，默认 ¥2.50；报表不读取订单表邮费列。

## 验证

在 `backend` 目录运行 `..\.venv\Scripts\python.exe -m pytest tests -q`。此测试只覆盖本地规则，不会连接或修改 MySQL。前端进入 `frontend` 目录运行 `npm run build`。

## 注意

MySQL 服务必须由用户/系统自行安装和启动，本程序不自带数据库服务。初始化需要目标数据库已存在。安全初始化只创建并使用 `app_*` 表；在应用连接账户权限允许的范围内，旧业务表均仅读取。
